# Core IR

`src/core` turns the parser's AST into a neutral intermediate representation (IR) that output
adapters consume. It knows Prisma's semantics and nothing about any target language or ORM.

```
schema.prisma -> parseSchema (AST) -> buildIr (IR) -> adapter.generate -> files + diagnostics
```

## How it works

`buildIr(ast)` (`src/core/build.ts`) is a pure function from `SchemaAst` to `IrSchema`
(`src/core/ir.ts`). The IR is plain, readonly JSON data. It describes the model in Prisma's own
terms (scalar types, native types, relations), but with Prisma's implicit defaults resolved, so
adapters do not have to re-implement them:

| Prisma | IR |
| --- | --- |
| `datasource.provider`, `schemas` | `IrSchema.provider` (null without a datasource), `IrSchema.schemas` |
| `model`, `@@map`, `@@schema`, `///` docs | `IrModel.name`, `dbName` (table name, always set), `schema`, `documentation` |
| field, `@map` | `IrField` (`kind`: `scalar`, `enum`, `relation`, `unsupported`), `dbName` (column name, always set) |
| `?`, `[]` | `isRequired`, `isList` |
| `@db.VarChar(100)` | `IrScalarField.nativeType = { name: 'VarChar', args: ['100'] }` |
| `@updatedAt` | `IrScalarField.isUpdatedAt` |
| `@default(...)` | `IrDefault`: `literal` or `function` with `generatedBy: 'database' \| 'client'` |
| `@id`, `@@id([a, b], name:, map:)` | `IrModel.primaryKey = { name, dbName, fields }` and `field.isId` |
| `@unique`, `@@unique` | `IrModel.uniques` (`IrIndex` with `kind: 'unique'`) and `field.isUnique` |
| `@@index`, `@@fulltext` | `IrModel.indexes` (`kind: 'normal' \| 'fulltext'`) |
| `@relation(fields:, references:, onDelete:, onUpdate:)` | `IrForeignKeyRelation` |
| two list relation fields | `IrManyToManyRelation` with a resolved `joinTable` |
| `enum`, `@map` on values, `@@map` | `IrEnum.dbName`, `values[].dbName` |
| `Unsupported("circle")` | `IrUnsupportedField.type = 'circle'` |
| `@relation(map: "fk")` | `IrForeignKeyRelation.dbName = 'fk'` |
| `@@ignore`, `@ignore` | `IrModel.isIgnored`, `field.isIgnored`, and `isIgnored` on the relations they touch |

Attributes are represented structurally (as the properties above), not as raw attribute lists.

What `buildIr` resolves:

- **Names.** Table, column and enum names fall back to the Prisma name. Constraint names
  without `map:` use Prisma's defaults (`<table>_pkey`, `<table>_<columns>_key`,
  `<table>_<columns>_idx`, `<table>_<columns>_fkey`), built from database column names. They are
  truncated like Prisma does it, to the provider's identifier limit (63 bytes on PostgreSQL and
  CockroachDB, 64 on MySQL, 128 on SQL Server, 10000 on SQLite).
- **Defaults.** `uuid()`, `cuid()`, `nanoid()` and `ulid()` are generated by Prisma Client
  (`generatedBy: 'client'`); the column has no database default. Everything else, including
  literals, `autoincrement()`, `now()` and `dbgenerated()`, is `'database'`.
- **Relations.** One relation per pair of relation fields, with the foreign-key owner as `from`.
  `onDelete`/`onUpdate` are effective values: explicit, or Prisma's defaults (`onDelete` is
  `SetNull` for optional relations and `Restrict` for required ones; `onUpdate` is `Cascade`).
  `referencesPrimaryKey` tells whether `references` is exactly the target's primary key.
  Scalar foreign-key fields get `isForeignKey: true`.
- **Ignored parts.** `@@ignore` models and `@ignore` fields are not in Prisma Client, but their
  tables, columns and foreign keys exist in the database (Prisma Migrate creates them). The IR
  keeps them and flags them with `isIgnored`. A relation is `isIgnored` when either relation
  field has `@ignore` or either model has `@@ignore`. Each adapter decides how much of an
  ignored part it emits.
- **Implicit many-to-many.** Prisma's join table conventions: table `_<RelationName>`; columns
  `A` and `B`, where `A` belongs to the model whose name sorts first (for self-relations, the
  field whose name sorts first); `(A, B)` is a primary key `_<t>_AB_pkey` on PostgreSQL and a
  unique index `_<t>_AB_unique` elsewhere; an index `_<t>_B_index`; and two cascading foreign keys
  `_<t>_A_fkey` and `_<t>_B_fkey`.

Names helpers (`src/core/names.ts`): `splitWords`, `toSnakeCase`, `toCamelCase` and
`toPascalCase`. They are Unicode-aware and treat acronyms as one word (`HTTPLog` becomes
`http_log`, `httpLog` and `HttpLog`).

### The adapter contract

`src/core/adapter.ts` defines what an output target implements:

```ts
interface Adapter<Options extends AdapterOptions = AdapterOptions> {
  readonly name: string;
  generate(ir: IrSchema, options?: Options): { files: { path: string; contents: string }[]; diagnostics: AdapterDiagnostic[] };
}
```

See [adapters.md](adapters.md) for the rules adapters follow and how to write one.

### Public API

The root entry point exports `buildIr`, the name helpers, the IR and adapter types,
`DiagnosticBag`, `formatDiagnostic`, `findRelation` and `generate(source, adapter, options?)`.
`generate` runs `parseSchema`, then `buildIr`, then the adapter, and returns a `ParseResult` that
keeps the parser's lint warnings.

```ts
import { buildIr, parseSchema } from 'prisma-x';

const parsed = parseSchema(source);
if (parsed.ok) {
  const ir = buildIr(parsed.value);
  for (const relation of ir.relations) console.log(relation.kind, relation.name);
}
```

## Enabling and disabling

The core is a library with no side effects. It runs only when `buildIr` or `generate` is
called, and the CLI always calls it. It does not need the wasm engine itself: you can pass any
`SchemaAst`, e.g. one built by hand in tests.

## Testing

```sh
pnpm vitest run test/core
```

- `test/core/ir.test.ts`: names, enums, field kinds and declaration order, defaults and
  `generatedBy`, keys and default constraint names (including truncation), referential action
  defaults, many-to-many ordering and join table names per provider, self-relations,
  `findRelation`, recovered foreign-key names and ignored parts, and IR built from hand-made ASTs.
- `test/core/names.test.ts`: word splitting and case conversion.
- `test/public-api.test.ts`: core modules never import from `src/adapters`.

## Limitations

- The IR holds what the AST holds: the engine's datamodel, plus custom foreign-key names,
  `@@ignore` models and `@ignore`/`Unsupported` fields recovered from the source (see
  [parser.md](parser.md#how-it-works)). Index details such as sort order, length, index type
  (`type: Hash`) and `clustered` are not carried; only the field names and the constraint name
  are.
- `relationMode = "prisma"` is ignored: the IR always describes database foreign keys.
- Composite types (MongoDB) and multi-file schemas are not supported.
- Views are not supported, because the parser does not enable the `views` preview feature.
